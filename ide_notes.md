# Заметки: Git в VS Code vs Терминал

## 3 вещи, которые удобны в VS Code для работы с Git

### 1. Просмотр истории коммитов (с GitLens)
В VS Code можно визуально изучить всю историю изменений файла — кто, когда и что менял. 
Благодаря расширению GitLens прямо в редакторе видно "авторство" каждой строки (git blame) 
без необходимости вводить команды в терминале. Это очень ускоряет анализ кода коллег.

### 2. Панель Source Control для быстрых операций
Через боковую панель можно за пару кликов выполнить основные операции: 
`git add`, `commit`, `push`, `pull`, `fetch`. Не нужно помнить флаги и синтаксис команд — 
всё интуитивно понятно через UI. Особенно удобно видеть список изменённых файлов и делать 
stage/unstage одним кликом.

### 3. Визуальный diff (сравнение версий файлов)
При клике на изменённый файл VS Code открывает наглядное сравнение: слева — старая версия, 
справа — новая, с подсветкой добавленных/удалённых строк. Это гораздо удобнее, чем читать 
вывод `git diff` в терминале, особенно при работе с большими файлами.

## 1 вещь, которую удобнее делать в терминале

### Автоматизация через bash-скрипты и работа на сервере
В терминале гораздо удобнее писать скрипты автоматизации (например, массовый коммит 
изменений в 100 файлах одной командой, настройка CI/CD, деплой). Кроме того, на удалённых 
серверах (по SSH) обычно нет графического интерфейса — только терминал. DevOps-инженер 
обязан уметь работать с Git в CLI, потому что в продакшен-среде у него будет только консоль.
